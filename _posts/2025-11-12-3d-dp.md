# The Problem

This is a classic DP problem where you are given a grid and you have to get to the bottom right corner with a maximum score with the twist of a knapsack like constraint.
The knapsack constraint makes this a 3D DP problem.

# Brute Force Approach

There is a brute force dfs approach but it is too slow as you have to make 2 recursive calls (right and down) for all 400 cells so it is O(2^400) which is too slow.

# Optimization

We can memoize the results in a 3D vector for (i,j,k) where i and j are the coordinates of the cell and k is the remaining capacity. 

Memo[i][j][rem] = the maximum score starting at i,j inclusively to n-1,m-1 with budget *rem* remaining at i,j with it originally being initialized to -1 (unvisited) and if it is impossible to get to the bottom right corner with remaining capacity rem, then it is set to -2.

So the answer is Memo[0][0][budget].

The base case is when you reach the bottom right corner (n-1, m-1) and you just return the score at grid[n-1][m-1].


# The Implementation
```cpp
class Solution {
public:
    int n, m;
    vector<vector<int>> *G;
    vector<vector<vector<int>>> memo;

    int UNVIS = -1;
    int IMP = -2;

    int cost(int x){
        return (x == 0) ? 0 : 1;
    }

    int dfs(int i, int j, int rem){
        if(i == n-1 && j == m-1) return (*G)[i][j];

        if(memo[i][j][rem] != UNVIS) return memo[i][j][rem];

        int best = IMP;

        if(j+1 < m){
            int c = cost((*G)[i][j+1]);
            if(rem - c >= 0){
                int right = dfs(i, j+1, rem-c);
                if(right != IMP) best = max(best, (*G)[i][j] + right);
            }
        }

        if(i+1 < n){
            int c = cost((*G)[i+1][j]);
            if(rem - c >= 0){
                int down = dfs(i+1, j, rem-c);
                if(down != IMP) best = max(best, (*G)[i][j] + down);
            }
        }

        return memo[i][j][rem] = best;
    }

    int maxPathScore(vector<vector<int>>& grid, int k) {
        n = grid.size();
        m = grid[0].size();
        G = &grid;

        memo.assign(n, vector<vector<int>> (m, vector<int> (k+1, UNVIS)));

        int ans = dfs(0,0,k);

        return (ans == IMP) ? -1 : ans;
    }
};

```

## C++ Implementation Notes

### `vector::assign`

**Purpose:** Replace contents and set size, filling with a value.

**Example (3-D memo):**
```cpp
memo.assign(n, std::vector<std::vector<int>>(m, std::vector<int>(k+1, UNVIS)));
```

**Contrast with `resize`:** `resize` changes size but preserves existing elements (up to the new size). `assign` discards existing contents and overwrites.

### Pointer vs Reference Wording

- **`*` in code** dereferences a pointer. It does not "get a reference."
- **`&` in an expression** takes the address (produces a pointer).
- A C++ reference is declared with `&` in the type (e.g., `const Grid&`), not obtained by writing `*` before a variable.

### The `G` Field

**What you have:**
```cpp
std::vector<std::vector<int>> *G;  // pointer to a grid
G = &grid;                          // store address of the caller's grid

// use it:
int x = (*G)[i][j];                 // dereference, then index
```

This is valid as long as `grid` outlives all uses (it does within `maxPathScore`/`dfs`).

**More idiomatic and safer alternatives:**

**Option A: pointer to const**
```cpp
const std::vector<std::vector<int>>* G;
G = &grid;
int x = (*G)[i][j];
```

**Option B: reference member (cleanest but needs constructor/init)**
```cpp
const std::vector<std::vector<int>>& G;
// then just use G[i][j] without dereferencing
```

If you keep the pointer style, prefer:
```cpp
const std::vector<std::vector<int>>* G;  // prevents accidental writes
```
