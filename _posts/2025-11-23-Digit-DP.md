# The Problem
Given a positive integer n, I have to return the number of distinct integers from 1 to n after removing all zeros.

# The Mathematical Solution

The key observation is that the set of distinct integers after removing all zeros are going to be <= n. $$g(x) \leq x \leq n$$

So we can break this into the *sum* of two cases:
1. numbers with fewer digits than n
2. numbers with the same number of digits as n

**Case 1:** Suppose n has k digits. A number with exactly L digits (where 1 <= L <= k-1) has the form
aL, aL-1, ..., a1 

and must satisfy the condition where ai must be in the range [1,9] for all i.

**Combinatorics Multiplication Principle:** When counting numbers with digit restrictions with a fixed number of allowed choices, then the total number of possible numbers is the product of the number of choices for each digit.

So by the *Combinatorics Multiplication Principle*:
the first digit has 9 choices,
the second digit has 9 choices,

the Lth digit has 9 choices.

The total number of valid L-digit numbers is (9^L)

Since there are many L-digit numbers where L ranges from 1 to k-1, we can sum up the number of valid L-digit numbers

$$\sum_{L=1}^{k-1} 9^L$$

**Case 2:** If we use the same logic as case 1, then we will count numbers that are greater than n. So we have to think of something different.

Let's say our n is a number whose digits are abcde and lets say the number we are counting is xyzwv.

To make sure xyzwv is less than abcde, we have to make sure that:
1. x are numbers less than a
2. y are numbers less than b
3. z are numbers less than c
4. w are numbers less than d
5. v are numbers less than e

If you think about it logically, if we pick an x < a then then the remaining digits y, z, w, v can be anything so there are 9^(remaining digits) possibilities. 
Then we can add the count of above with the following
If we pick an y < b then then the remaining digits z, w, v can be anything so there are 9^(remaining digits) possibilities.
So on and so forth.

Now here is an edge case. What if we encounter a 0 in n. Very Simply we just stop because we cannot have a number with a digit less than 0 in it.

If n itself has no zero, then we can increment the count by 1 since we haven't counted n yet.

$$(k\text{-digit part}) = \sum_{i=0}^{k-1} (d_i - 1) 9^{k-i-1} + \begin{cases} 1, & \text{if } n \text{ has no zero digit,} \\ 0, & \text{otherwise.} \end{cases}$$

$$k-i-1$$ is the number of digits left to choose for the remaining digits.

Mathematical Implementation:
```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    long long countDistinct(long long n) {
        string s = to_string(n);
        int k = (int)s.size();

        // precompute powers of 9
        long long pow9[20];
        pow9[0] = 1;
        for (int i = 1; i < 20; ++i) {
            pow9[i] = pow9[i - 1] * 9;
        }

        long long ans = 0;

        // 1) numbers with fewer digits than n
        for (int L = 1; L < k; ++L) {
            ans += pow9[L];      // 9^L numbers with no zero digit
        }

        // 2) numbers with same number of digits as n
        bool hasZero = false;
        for (int i = 0; i < k; ++i) {
            int d = s[i] - '0';
            int remaining = k - i - 1;

            if (d == 0) {
                hasZero = true;
                break;
            }

            // digits 1..(d-1) at this position, then any non-zero digits for the rest
            ans += (long long)(d - 1) * pow9[remaining];
        }

        // if n itself has no zero digit, count it
        if (!hasZero) ans += 1;

        return ans;
    }
};

```

# Digit DP Approach
You can *NOT* brute force this problem because n = 10^15.

This is a clear candidate for digit dp because we have to count how many integers in a range that have some property. The crux of it lies in the fact that the necessary information for each state doesn't have to be the *entire* integer but rather some information pertaining to the digits. If the range is [a,b] then we return fn(b) - fn(a-1).

If we are doing dp then we need to determine the states of the dp.

The obvious one is the current index in the string representation of the number

Another super common state for digit dp problems is whether the number we are constructing matches the prefix of the number we are looking at. If the prefix is matching then we are *constrained*, and if not then we are *unconstrained*. This will be a boolean state.

Then another equally important state that is often used is to build numbers with leading zeros and most importantly NOT have it affect the answer. If I haven't officially started constructing the number then I *can* place a zero in the current position and still have it count as a valid number. But if I have already started constructing the number then I *cannot* place a zero in the current position and still have it count as a valid number. This will be a boolean state.

So we have 3 states:
1. The current index in the string representation of the number
2. Whether the number we are constructing matches the prefix of the number we are looking at
3. Whether we have already started constructing the number

If we are constrained the numbers we can use are from 0 to the current digit, and if it's not constrained then we can use 1 to 9.

```cpp
int curr_digit = s[i] - '0'; // where s is the string representation of the number
int mxdigit = constrained ? curr_digit : 9; // if constrained then the max digit is the current digit, otherwise it is 9
```

So if we are thinking of the general recrurence relation then let's consider if we have began or not. If we have not begun then we can use 0 as a digit and *we will still be constrained* meaning the prefix is still matching ONLY if the mxdigit is 0. If mxdigit is not 0 and we place a 0 we become unconstrained because 0 < limit.

```cpp
if(!began){
    int nc = constrained && (mxdigit == 0);
    ans += solve(idx=idx+1, str=str, constrained=nc, began=false);
}   
```

Now we are considering where we have begun, then we have the choice to place digits 1 thru 9. If the digit we are considering is > mxdigit then we break since we are only allowed to place digits <= mxdigit.

Similarly if we come up with a new constrained state, nc, where it is the current state of constrained AND whether the current digit is equal to mxdigit (makes sense right? We are still matching the prefix).

```cpp
for(int d = 1; d <= 9; d++){
    if(d > mxallowed) break;

    bool nc = constrained && (mxallowed == d);

    ans += solve(idx=idx+1, str=str, constrained=nc, began=true); // began is true because we are quite literally constructing the number now
}
```

# Putting it all together

```cpp
class Solution {
public:
    long long dp[20][2][2];
    long long solve(int idx, string str, bool constrained, bool began){
        if(idx == str.size()){
            if(began) return 1;
            else return 0;
        }

        if(dp[idx][constrained][began] != -1) return dp[idx][constrained][began]; 

        long long ans = 0;

        int mxdigit = str[idx] - '0';
        int mxallowed = (constrained) ? mxdigit : 9;

        if(!began){
            bool nc = constrained && mxallowed == 0;
            ans += solve(idx+1, str, nc, false);
        }
        

        for(int d = 1; d <= 9; d++){
            if(d > mxallowed) break;

            bool nc = constrained && (mxallowed == d);

            ans += solve(idx+1, str, nc, true);
        }

        return dp[idx][constrained][began] = ans;
    }

    long long countDistinct(long long n) {
        string str = to_string(n);

        memset(dp, -1, sizeof(dp));

        return solve(0,str,true,false);
    }
};
```
